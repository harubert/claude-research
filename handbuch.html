1. Installation

Dieses Template benötigt drei Komponenten. Die gesamte Einrichtung dauert etwa drei Minuten.

Visual Studio Code

Lade Visual Studio Code herunter und installiere es. Verfügbar für macOS, Windows und Linux.

Claude Code Extension

Installiere die Claude Code Extension aus dem VS Code Marketplace. Du brauchst einen Anthropic-Account (Claude) — die Anmeldung erfolgt direkt in VS Code.

Python 3

Python wird für das Build-Script benötigt, das den Artikel zusammenbaut.

macOS: python.org/downloads/macos
Windows: python.org/downloads/windows — bei der Installation „Add to PATH" aktivieren
Linux: Meist vorinstalliert — prüfen mit python3 --version

fal.ai API-Key (optional)

Nur nötig, wenn du KI-generierte Hintergrundbilder für die Präsentation möchtest. Erstelle einen kostenlosen Key auf fal.ai/dashboard/keys und trage ihn in API Key.js ein.

Los geht's

Öffne den Template-Ordner in VS Code, öffne das Claude-Panel und tippe: Leg los

Claude stellt dir einige Fragen zu Thema, Veranstaltung und Umfang — danach läuft der gesamte Workflow automatisch: Quellenrecherche, Kapitel schreiben, Präsentation erstellen.

2. Konzept und Arbeitsweise

Dieses Template erzeugt einen vollständig statisch gehosteten akademischen Artikel mit interaktivem Quellenmanagement. Claude Code dient als Schreib- und Rechercheassistent — du behältst die inhaltliche Kontrolle.

Das Besondere am Konzept:

  • Keine Datenbank, kein CMS. Alle Inhalte liegen als Markdown-Dateien und eine JSON-Quellendatei vor. Ein Python-Script baut daraus eine vollständige HTML-Seite und einen LaTeX-Export.
  • Funktioniert lokal und online. Alle Seiten laufen direkt über file:// ohne Webserver — und genauso auf jedem normalen Hosting.
  • KI als Assistent, nicht als Autor. Claude recherchiert Quellen, schlägt Strukturen vor und liefert Entwürfe. Du entscheidest, was bleibt, und überarbeitest.
  • Zwei Export-Formate: HTML (mit interaktiven Funktionen) und LaTeX (für professionellen Druck via Overleaf).

Typischer Workflow:

  1. Claude befüllt meta.json mit deinen Angaben
  2. Recherchiert 5–10 Kernquellen, erster Build — du siehst sofort die Quellenübersicht
  3. Legt Kapitelgerüste an, Build — du siehst die Seitenstruktur
  4. Recherchiert weitere Quellen (bis 100–150) mit URL-Verifikation
  5. Leitet aus den Forschungslücken fünf Forschungsdesiderata ab (offene Forschungsvorhaben)
  6. Schreibt die Kapitel aus — Build nach jedem Kapitel
  7. Erstellt die Präsentation mit KI-Folienbildern
  8. Führt zwei Prüfdurchgänge und ein abschließendes Complete Review durch

4. Fachartikel — Funktionen

Der Fachartikel (standalone.html) enthält mehrere interaktive Elemente:

Kopfleiste

Fixe Navigationsleiste oben auf allen Seiten — Artikel, Quellen, Folien, Handbuch. Im Artikel rechts zusätzlich die Werkzeuge; eine dünne Linie zeigt den Lesefortschritt.

Dokumentinfo
Export (LaTeX / ZIP)
Drucken
Nach oben (erscheint beim Scrollen)

Beim Drucken (Browser-Dialog oder PDF) werden diese Elemente automatisch ausgeblendet.

Info-Panel (Dokumentstatistik)

Zeigt Kapitelanzahl, Quellenanzahl, Wortzahl und geschätzte Seitenzahl (A4 und A5). Standardmäßig ausgeblendet — wird über das Info-Symbol in der Kopfleiste ein- und ausgeblendet.

Inline-Zitationen (anklickbar)

Alle Quellenverweise im Text im Format (Autor, Jahr) sind anklickbar. Ein Klick öffnet eine Quellenkarte mit Titel, Autoren, Jahr, Journal, Score, Badges und Abstract. Enthält einen Link zur Primärquelle (DOI oder URL).

Inhaltsverzeichnis

Alle zehn Kapitel mit Sprunglinks. Wichtig: Jedes Kapitel muss mit einer H1-Überschrift (# Kapitelname) beginnen — sonst bleibt das Inhaltsverzeichnis leer.

Weiterführende Literatur (Ende des Artikels)

Alle zitierten Quellen mit Score ≥ 9 — die hochwertigsten Empfehlungen. Mit Badges, Sternebewertung und DOI-Links.

Vollständiges Quellenverzeichnis (Anhang)

Alle Quellen kompakt, zweispaltig, mit Quellen-ID und Markierung ob zitiert. Dient als Referenz und Druckbeilage.

5. Export (LaTeX + Web-Paket)

Das Export-Symbol in der Kopfleiste des Artikels öffnet ein Overlay mit zwei Tabs:

Tab 1: LaTeX

Erzeugt eine .tex-Datei für professionellen Druck (Overleaf, pdflatex).

Tab 2: Web-Paket (ZIP)

Erstellt ein ZIP mit allen Seiten für eine Website: Artikel, Quellen, Handbuch, Präsentation, Landingpage und Stylesheets. Den Inhalt einfach per SFTP/FTP in ein Verzeichnis auf einem Webserver hochladen — fertig. Kein Server-Setup, keine Datenbank, keine Installation nötig.

Hinweis: Folienbilder (KI-generiert) werden nicht eingebettet. Für Folien mit eingebetteten Bildern verwende den Deployment-Export direkt in der Präsentation.

LaTeX-Optionen im Detail:

OptionWerteHinweis
FarbmodusFarbe / Schwarz-WeißS/W: alle Badges in Grautönen
Schriftgröße9 / 10 / 10.5 / 11 pt11 pt ist Standard; 10 pt für Fachbücher üblich
Zeilenabstand1.0 / 1.15 / 1.251.0 = klassischer Buchdruck
RänderEng (±1.5 cm) / Normal (±1.8 cm) / BundstegBundsteg: innen 2.5 cm, außen 1.5 cm, twoside — für Buchbindung

Die Seitenschätzung wird live berechnet und berücksichtigt alle vier Parameter. Die tatsächliche Seitenzahl kann durch Tabellen, Abbildungen und Formeln abweichen.

Download: Die .tex-Datei wird direkt im Browser generiert und heruntergeladen — kein Server nötig. Die Datei ist für pdflatex (Overleaf, TeX Live, MiKTeX) vorbereitet.

6. Quellenverzeichnis

Das interaktive Quellenverzeichnis bietet:

  • Volltextsuche über Titel, Autoren, Abstract und Notizen
  • Filter nach Typ (Journal, Konferenz, Buch, Preprint, Bericht, Web), Sprache, Badges und Score
  • Sortierung nach Score, Jahr, Titel
  • Zitations-Backlinks: Bei zitierten Quellen erscheinen nummerierte Marken (1, 2, 3 …), die direkt zur Textstelle im Artikel springen
  • Qualitätsbadges, Score mit Sternebewertung, Abstract-Vorschau, DOI/URL-Links, APA-Zitat kopieren
  • Live-Aktualisierung (Play-Symbol in der Kopfleiste): lädt die Seite alle 20 Sekunden neu — praktisch, um die Recherche live mitzuverfolgen

ÖsterreichÖsterreichischer Bezug
Open AccessFrei zugänglich, keine Paywall
PaywallNur mit Institutionszugang oder Bezahlung verfügbar

Im ArtikelDiese Quelle wird im Artikel direkt zitiert

Eigene Badges

Neben den Standard-Badges lassen sich beliebig viele eigene, themenspezifische Badges anlegen — etwa Schulstufen, Länder, Methoden oder Zielgruppen. Claude legt bei der Recherche selbst passende Badges an; du kannst jederzeit weitere ergänzen. Jedes Badge, das in sources.json vorkommt, erscheint im Quellenverzeichnis automatisch als Filter (mit Anzahl). Beschriftung, Icon und Farbe stehen in content/meta.json:

"custom_badges": {
  "sek1":    { "label": "SEK I",     "desc": "Sekundarstufe I",        "icon": "school", "color": "#0e7490" },
  "lehramt": { "label": "Lehramt",   "desc": "Lehrer*innenbildung",    "icon": "users" },
  "dach":    { "label": "D-A-CH",    "desc": "Deutschsprachiger Raum", "icon": "globe-pin" }
}

Ohne Eintrag in custom_badges erscheint ein Badge mit seinem Schlüssel als Beschriftung und einem neutralen Etikett-Icon. Verfügbare Icons stehen in assets/icons.js.

8. Qualitätsbewertung (Score)

Jede Quelle erhält einen Score von 3–10. Er setzt sich aus drei Kriterien zusammen:

KriteriumSkalaBedeutung
Authority1–4Herkunft und wissenschaftliche Reputation (Peer-Review-Journal = 4, Blog = 1)
Recency1–3Aktualität (2023–2026 = 3, 2019–2022 = 2, vor 2019 = 1)
Relevance1–3Thematische Nähe zum Kernthema des Artikels (siehe nächstes Kapitel)

Score = Authority + Recency + Relevance (Maximum 10). Farbcodierung:

9–10: Exzellent — Weiterführende Literatur
7–8: Gut — solide Fachliteratur
5–6: Mittel — ergänzend nutzbar
3–4: Schwach — nur als Hintergrund

9. Relevanz-Kategorien anpassen

Die Relevanz-Dimension (1–3) muss zum Thema deines Artikels passen — nicht jeder schreibt über dasselbe Thema. Die Beschreibungen werden über content/meta.json gesteuert:

{
  "relevance_topic": "KI im Geometrieunterricht",
  "relevance_3": "Direkt: KI + Geometrie + Bildung",
  "relevance_2": "KI + Mathematik oder Geometrie + Didaktik",
  "relevance_1": "Allgemein KI-Bildung, Rahmendokumente"
}

Diese Texte erscheinen im Quellenverzeichnis bei der Bewertungsmethodik. Claude verwendet sie außerdem als Leitfaden, um neue Quellen korrekt einzuordnen.

Beispiel für ein anderes Thema:

{
  "relevance_topic": "Nachhaltigkeit in der Architekturausbildung",
  "relevance_3": "Direkt: Nachhaltige Architektur + Hochschuldidaktik",
  "relevance_2": "Architekturausbildung oder Nachhaltigkeitsdidaktik allgemein",
  "relevance_1": "Allgemeine Hochschuldidaktik, Rahmendokumente"
}

Wenn du die Felder nicht befüllst, verwendet build.py generische Fallback-Texte.

10. Abbildungen einbinden

Abbildungen werden im Ordner figures/ abgelegt und im Kapitel-Markdown referenziert:

![Beschriftung der Abbildung](figures/dateiname.png)

Der Build erzeugt daraus automatisch:

  • HTML: <figure>-Element mit Abbildung N:-Nummerierung und Bildunterschrift
  • LaTeX: \begin{figure}...\includegraphics...\caption{...}\end{figure} mit automatischer Nummerierung und Abbildungsverzeichnis

Unterstützte Formate: PNG, JPG, SVG (nur HTML), PDF (nur LaTeX).
Empfehlung für maximale Kompatibilität: PNG verwenden.

11. Build-System

Der gesamte Artikel wird durch ein einziges Python-Script erzeugt:

python3 build.py

Das Script liest:

  • content/meta.json — Titel, Autoren, Abstract, Kapitelliste, Relevanz-Kategorien
  • content/01_einleitung.md bis 10_ausblick.md — Kapitelinhalte (Markdown)
  • sources/sources.json — alle Quellen mit Metadaten
  • assets/css/paper.css — Stylesheet

Es erzeugt:

  • standalone.html — vollständiger Artikel mit Zitationssystem und LaTeX-Export-Overlay
  • standalone.tex — LaTeX-Datei (Farbe)
  • standalone_sw.tex — LaTeX-Datei (Schwarz-Weiß)
  • quellen.html wird aktualisiert (Quelldaten, Zitations-Backlinks und Relevanz-Texte eingebettet)

Zitationserkennung: Das Script erkennt automatisch alle APA-Zitate im Format (Nachname, Jahr) im Text, ordnet sie den Quellen in sources.json zu und erzeugt anklickbare Spans mit Quellenkarten-Overlay.

Wichtig: Nur das Format (Nachname, Jahr) wird erkannt — nicht [S001] oder andere Formate. Der Nachname muss exakt mit dem ersten Eintrag in authors in sources.json übereinstimmen.

12. Neue Quellen hinzufügen

Neue Quellen werden in sources/sources.json eingetragen. Die nächste freie ID steht im CLAUDE.md-File des Projekts.

Schema einer Quelle:

{
  "id": "S001",
  "title": "Titel des Werks",
  "authors": ["Nachname, V.", "Nachname2, V2."],
  "year": 2025,
  "journal": "Zeitschrift oder Verlag",
  "type": "journal",
  "lang": "en",
  "authority": 4,
  "recency": 3,
  "relevance": 3,
  "score": 10,
  "badges": ["peer", "openaccess"],
  "abstract": "Kurzzusammenfassung auf Deutsch.",
  "doi": "10.xxxx/xxxxx",
  "url": "https://...",
  "local": null,
  "retrieved": "2026-03-23",
  "notes": ""
}

Nach dem Eintrag: Im jeweiligen Kapitel-Markdown zitieren (Nachname & Nachname, Jahr) und im Literaturabschnitt am Kapitelende eine APA-7-Referenz ergänzen. Dann python3 build.py ausführen.

Zuletzt content/meta.json → source_count aktualisieren.

14. Forschungsdesiderata

Nach der Literaturarbeit leitet Claude aus den gefundenen Lücken fünf Forschungsdesiderata ab — konkrete Forschungsvorhaben, die in der recherchierten Literatur noch nicht oder nur unzureichend bearbeitet sind. Sie stehen in content/forschungsdesiderata.md und erscheinen im Artikel als eigener Abschnitt nach dem letzten Kapitel.

Jedes Vorhaben enthält:

  • Titel — prägnant, als möglicher Projekttitel formuliert
  • Forschungslücke — was die Literatur bisher nicht beantwortet, mit Belegen (Autor, Jahr)
  • Forschungsfrage — eine präzise, prüfbare Frage
  • Mögliches Design — Methode, Stichprobe, Setting (z. B. Quasi-Experiment mit 6 Klassen der Sekundarstufe I)
  • Erwarteter Beitrag — für Forschung und Praxis, ggf. mit Österreich-Bezug

Format in Markdown

## 1. Projekttitel

**Forschungslücke:** … (Autor, Jahr) …
**Forschungsfrage:** …
**Mögliches Design:** …
**Erwarteter Beitrag:** …

15. Prüfdurchgänge und Complete Review

Vor der Übergabe prüft Claude das Ergebnis in drei aufeinander aufbauenden Durchgängen. Gefundene Fehler werden sofort behoben, danach wird neu gebaut.

Prüfdurchgang 1 — Quellen und Zitate

Jedes Inline-Zitat hat einen Eintrag in sources.json, kein [S…]-Muster im Text, Literaturlisten am Kapitelende vollständig in APA 7, Scores = Authority + Recency + Relevance, keine doppelten Quellen, URLs und DOIs plausibel.

Prüfdurchgang 2 — Inhalt und Sprache

Roter Faden über alle Kapitel, Forschungsfragen aus Kapitel 1 im Fazit beantwortet, Zahlen und Aussagen durch Quellen gedeckt, Gender-Sternchen durchgängig, keine Floskeln, keine Emojis, österreichische Variante, Forschungsdesiderata klar von der Literatur abgeleitet.

Complete Review — Gesamtabnahme

Alle Ausgaben gemeinsam: Build fehlerfrei, Inhaltsverzeichnis vollständig, Artikel, Quellenverzeichnis, Präsentation und Startseite konsistent (Titel, Datum, Quellenzahl), Folien mit Artikel abgeglichen. Ergebnis wird in content/review.md protokolliert.

16. Designsystem und Icons

Alle Seiten teilen ein gemeinsames Designsystem — tiefes Nachtblau, ein kräftiges Primärblau und ein sparsam eingesetzter Signal-Akzent. Überschriften in Fraunces, Oberfläche in Inter, alle Schriften lokal eingebunden.

  • assets/css/site.css — Farben, Schriften, Kopfleiste, Buttons, Badges
  • assets/css/paper.css — Typografie des Artikels
  • assets/theme.js — Stil-Umschalter (sechs Stile)
  • assets/icons.js — einheitliches SVG-Icon-Set. In HTML: <span data-icon="book"></span>, in JavaScript: icon("book"). build.py liest dieselbe Datei.

Keine Emojis in Oberflächen und Texten — ausschließlich SVG-Icons aus icons.js.

Sieben Stile zum Umschalten

Über den Stil-Button in der Kopfleiste (auf der Startseite oben rechts) lassen sich Startseite, Artikel, Quellenverzeichnis und Handbuch in sieben Stilen anzeigen: Akademie (Standard), Print (nüchtern schwarz-weiß wie eine Drucksache), Klassik (Bordeaux, Creme, Playfair), Nacht (Dunkelmodus), Labor (technisch, Space Grotesk), Wald (Tannengrün, Ocker) und Minimal (Schwarz-Weiß mit einem Akzent). Die strengen Stile (Print, Minimal, Labor, Klassik) haben eigene Badge- und Filterformen.

Die Wahl wird im Browser gespeichert und gilt für alle Seiten. Technisch: assets/theme.js setzt <html data-theme="…">, die Stile selbst sind Token-Sätze in assets/css/site.css. Per URL lässt sich ein Stil direkt setzen, z. B. quellen.html?theme=print.

Schrift im Artikeltext

Im selben Menü: Schrift im Text — Auto (Vorgabe des Stils), Serif oder Serifenlos — und Schriftgröße (Klein, Normal, Groß). Per URL: standalone.html?font=sans&size=l.

Der LaTeX-Export übernimmt die Wahl automatisch als Vorbelegung (Serif = Charter, Serifenlos = Helvetica) und lässt sich im Export-Dialog umstellen. Für die vom Build erzeugten .tex-Dateien gilt "latex_font": "serif" bzw. "sans" in content/meta.json.
